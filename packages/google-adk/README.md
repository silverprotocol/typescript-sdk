# @silverprotocol/google-adk

AgJSON normalizer for the **official Google Agent Development Kit** —
[`@google/adk`](https://github.com/google/adk-js) (ADK `Event` / Gemini
`Content.parts[]` → `AgEvent[]`). It **sits on top of your ADK runner** and
translates the events it yields into framework-neutral AgJSON; it doesn't
replace the SDK you already use.

## Install

```sh
npm install @silverprotocol/google-adk @google/adk
```

`@silverprotocol/core` is a required peer (pulled in automatically). `@google/adk`
is the Google ADK itself — you need it to *produce* the events. (The normalizer
guards ADK `Event`s structurally, so if you only feed it already-captured events
it's just a type-level peer.)

## Usage

> **Usage semantics (spec draft.3 and draft.5).** `usage.inputTokens` is Gemini's cache-inclusive `promptTokenCount`, with `cacheReadTokens` (`cachedContentTokenCount`) its breakdown, never an addition (generateContent route). `usage.outputTokens` includes reasoning: the facet folds Gemini's sibling `thoughtsTokenCount` into `outputTokens` (candidates + thoughts, guarded by Gemini's own total so an already-inclusive endpoint is not double-added), and `reasoningTokens` is the breakdown — never add the two. `inputTokens + outputTokens + (toolUseInputTokens ?? 0) == totalTokens` holds on every Gemini response. On the Gemini Live API (`runLive`), Gemini reports its output as `responseTokenCount` and its own total can leave thoughts out, so the facet derives `totalTokens` as `inputTokens + outputTokens + (toolUseInputTokens ?? 0)` and carries Google's figure on `totalTokensRaw`, only where it differs. That total is the one Gemini's generateContent surface reports for the same counts, not a billing figure: the Live API prices per modality. Known upstream gap: on `@google/adk`'s Interactions-API route (`useInteractionsApi`) the SDK synthesizes `usageMetadata` without thoughts, so there `outputTokens` is exclusive and `reasoningTokens` absent.

> **Tool outcomes (spec draft.4, §8.0 item 25).** ADK reports a failed tool call as a `functionResponse` whose `response` carries Gemini's `error` key. The facet maps it to `tool.done` `outcome:"error"` with `isError:true`, plus `errorText` when `error` is a string and `errorCode` from `error_code`/`errorCode`. This covers an unresolvable tool name, a thrown tool (including a thrown MCP call) and several built-in tools. An MCP result with `isError:true` also reads `"error"` with `isError:true`. A declined approval (a FunctionTool or SecurityPlugin rejection, a policy-engine DENY, `CONFIRMATION_REJECTED`) reads `"denied"`. ADK's pending-confirmation placeholder stays `"ok"`; the pause rides `hitl.ask`. The response always stays verbatim in `content`. So a tool of yours that returns `{error: …}` as ordinary data now reads as a failure.

```ts
import { LlmAgent, InMemoryRunner } from "@google/adk";
import { createAdkNormalizer } from "@silverprotocol/google-adk";

// Build your ADK agent + runner as usual — this package normalizes what it emits.
const agent = new LlmAgent({
  name: "assistant",
  model: "gemini-3.8-flash",
  instruction: "Use the echo tool.",
});
const runner = new InMemoryRunner({ agent });
const session = await runner.sessionService.createSession({
  appName: runner.appName,
  userId: "user-1",
});

const n = createAdkNormalizer();
const agEvents = [];
for await (const native of runner.runAsync({
  userId: session.userId, // must match the session you created
  sessionId: session.id,
  newMessage: { role: "user", parts: [{ text: "call the echo tool" }] }, // role is REQUIRED: adk-js drops role-less turns from tool-loop replays (400)
}))
  agEvents.push(...n.push(native)); // one ADK Event → 0+ AgEvents
agEvents.push(...n.flush());        // seal anything still open
```

`push()` returns the `AgEvent[]` synthesized from each native ADK `Event`;
`flush()` drains buffered end-of-stream state. Any async/sync iterable of ADK
`Event`s works — a live `runAsync()` run, or events you captured earlier.

> **ADK pauses and Workflow runs.** Construct one normalizer per `runAsync()` call and call `flush()` once when it ends. When ADK pauses a run for a human, the turn closes from `push()` as `turn.done` with `outcome: "paused"` and `finishReason: "paused"`, carrying one ask per pending request (spec §8.0 item 26). ADK's reserved calls map as follows: `adk_request_input` becomes a `text` ask (`form` when it declares a `response_schema`); `adk_request_credential` becomes an `auth` ask; `adk_request_confirmation` becomes an `approval` ask. Each ask's `toolCallId` is the reserved call's id, the id ADK accepts as the answer (`resumeBinding: "id"`), and the original tool call's id rides `metadata.originalFunctionCallId`. On a graph `Workflow`, a node's own final answer never ends the run.
>
> **Completion (spec §8.0 host obligation 4).** ADK's stream carries no end marker for a completed run. Opt in with `createAdkNormalizer({ hostCompletion: true })` and push `{ type: "__host_complete__" }` after `runAsync()` returns NORMALLY, never after a cancel, an abort signal or a thrown error, and before `flush()`. The turn then closes from `push()`: `paused` if an ask is pending, `success` otherwise; a non-HITL long-running call that is still unanswered leaves the turn to `flush()`. With the option on, a success close waits for that event, so SequentialAgent roots and after-agent callback content no longer land after the terminal. Without the opt-in, or when the host doesn't feed the event, a completed Workflow run closes at `flush()` as `turn.abort` (`stream-truncated`), with its usage on the `message.end`. The `__host_complete__` object is a host↔facet contract input, like the error sentinel of host obligation 1, not an ADK event. So with the option off the normalizer ignores it on purpose, and the §8.0 rule against silently dropping a framework event does not apply to it.

> **Errors the runtime throws (spec §8.0 host obligation 1).** When ADK throws instead of ending the stream (for example its LLM-call limit), catch it and push `{ type: "__host_error__", code, message, usage? }` (exported as `ADK_HOST_ERROR_TYPE`) before `flush()`: the open turn closes `turn.error` with that code and message, and with no turn open a fresh terminal turn, `turn_<invokeId>_host_error_<n>`, carries it. The sentinel may be the caught Error itself with `type` and `code` assigned; its message is kept.

> **Ids across invokes (spec §8.0).** A host that folds several invokes of one conversation into one `reduce()` needs turn and message ids that never repeat across them. ADK's `invocationId` alone doesn't guarantee that: ADK-JS mints a fresh one on every `runAsync()`, but ADK-Python's resumable resume reuses `invocation_id`. So every turn id carries a per-invoke stem, `turn_<invokeId>_<invocationId>`, and its message id is `msg_<turnId>`. By default each normalizer draws a random `adk_<16 hex>` stem once, when it is constructed. Pass `createAdkNormalizer({ invokeId })` only to make the output reproducible (tests, replay), and then keep it unique per invoke within a fold.

> **Live sessions (`runLive`).** One live session is one ADK invocation that can hold several model generations. On a barge-in, ADK sends `interrupted: true` first, then the interrupted generation's usage and `turnComplete`, then the reply. The interrupted generation closes as `turn.abort` (`interrupted`) on its own `turnComplete`, with its usage on the `message.end`, and the reply opens the next turn, `turn_<invokeId>_<invocationId>_g1`. A transcription reads once: ADK's `finished` transcription is not re-emitted when it repeats the chunks already streamed. A generation that follows a completed reply with no barge-in still lands in the closed turn unless you opt into `hostCompletion`, which defers that close. When text is buffered at the interrupt, ADK yields only the text aggregate, without the flag, so the turn closes at `flush()` as `stream-truncated`.

> **Credential material (spec §8.0 item 28).** ADK credential material is the one exception to the compatibility table's "carried losslessly". In an `adk_request_credential` call and its reply, the facet carries only the auth-config members it knows to be non-secret. In `state.delta` it omits every entry that holds an ADK credential object, and every `temp:` entry. A patch that is itself an ADK credential object is emitted as `{}`, other keys in that patch included. Inside a `provider-raw` carry it reduces each ADK credential object, and each response to `adk_request_credential`, to its non-secret members; when that reduces a node's output, the text part ADK renders from that output is skipped too. A credential an application keeps in a shape of its own is not recognised, and rides unchanged.

Then fold the resulting `AgEvent`s into messages and turns with
`@silverprotocol/core`'s `reduce()` — the same client code regardless of which
framework produced the stream.
